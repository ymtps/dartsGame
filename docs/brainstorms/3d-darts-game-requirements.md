# Web 3D ダーツゲーム

## Problem Frame

ブラウザで手軽に遊べるリアルな3Dダーツゲームが存在しない。
一般ユーザーがインストール不要でCPU対戦できる、物理演算付き3Dダーツゲームを提供する。

---

## Requirements

**スタート画面**
- R1. スタート画面でゲームモードを選択できる（501/301 または クリケット）
- R2. 501モードと301モードは同一ルールで開始点数のみ異なる（スタート画面で選択）

**3D表示・カメラ**
- R3. ダーツボードと投擲エリアを3Dで表示する（Three.js使用）
- R4. プレイヤー視点（ダーツボードを正面に見る一人称的アングル）でゲームを進行する
- R5. ダーツが投げられた後、弾道と着弾を3Dアニメーションで表示する

**投擲操作（クリックタイミング方式）**
- R6. マウスカーソルの位置でボード上の照準を指定する
- R7. 照準確定後、画面上の精度インジケーター（左右に往復するバー）が動作する
- R8. バーが中央に近いタイミングでクリックするほど照準通りに刺さる；端に近いほどズレが生じる
- R9. 1ターンにダーツ3本を投げる。各投擲でR6〜R8の操作を繰り返す

**弾道・物理**
- R10. ダーツの飛翔は数式による弾道計算（放物線＋微小ランダム誤差）で実現する
- R11. 着弾後のダーツはボードに刺さった状態で表示され、そのターンの3本投擲が完了するまで残る。ターン終了後はそのターンのダーツをすべてボードから除去してから次のプレイヤーの投擲を開始する。

**スコアリング**
- R12. ダーツボードの各領域（シングル・ダブル・トリプル・Bull・Outer Bull）を正確に判定する
- R13. スコアはリアルタイムで画面に表示する

**501/301ルール**
- R14. プレイヤーとCPUが交互に3本ずつ投げ、合計点数を減算していく
- R15. ちょうど0になった側が勝ち（ダブルフィニッシュ不要のカジュアルルール）。0を超えてしまった場合はバスト（そのターン無効・スコアを元に戻す）

**クリケットルール**
- R17. 対象数字は15・16・17・18・19・20・Bull（25）
- R18. 各数字を3回ヒット（トリプルは1投で3カウント）でクローズ
- R19. クローズ済みかつ相手がクローズしていない数字にヒットした場合、その点数を加算する
- R20. 全対象数字をクローズし、かつ相手と同点以上のスコアで勝利

**CPU AI**
- R21. CPUはターン毎に目標数字を決定し、設定された精度で投擲をシミュレートする
- R22. CPUの難易度は3段階（簡単・普通・難しい）で実装し、スタート画面で選択できる
- R23. CPUの投擲もアニメーションで表示する（瞬時に結果表示ではなく）

**ゲームフロー**
- R24. 勝敗が決まったらリザルト画面を表示し、リプレイまたはモード選択に戻れる
- R25. ゲーム中にいつでもスタート画面に戻れる（リセット機能）

---

## Success Criteria

- ブラウザを開いてすぐゲームを開始でき、インストール不要で動作する
- クリックタイミング操作が直感的で、初見でも意図した方向に投げられる
- 501・クリケット両モードのルールが正確に動作し、勝敗が正しく判定される
- CPU AIが明確に手番を実行し、対戦ゲームとして成立している

---

## Scope Boundaries

- オンライン対戦・ローカル対戦（2プレイヤー同一端末）は対象外
- リーダーボード・オンラインスコア保存は対象外
- 練習モード（ルールなし自由投擲）は対象外
- スマートフォン・タッチ操作への最適化は対象外（PCブラウザのみ）
- キャラクターカスタマイズ・アバターは対象外

---

## Key Decisions

- **弾道計算方式**: フルリアルタイム物理（Cannon.js剛体飛行）ではなく、数式弾道計算＋着弾時のみCannon.js判定を採用。理由：操作感の安定性とCPU AI実装の容易さを優先
- **技術スタック**: Three.js（3D描画）＋ Cannon.js（着弾判定）。追加のバックエンドなし、静的サイトとして動作させる

---

## Dependencies / Assumptions

- ゲームはブラウザの静的HTMLとして動作する（サーバー不要）
- Three.js（r150以上、モジュールビルド）および cannon-es（v0.20以上 — 旧Cannon.jsのメンテナンス継続フォーク）をCDNまたはnpmバンドラーで導入する
- 3Dモデルはコード生成（ジオメトリ）で対応し、外部3Dアセットファイルは使用しない（当初）
